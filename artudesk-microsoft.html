Política de privacidad para Windows

Última actualización: 17 de noviembre de 2026

Esta política describe el tratamiento de información en la versión de escritorio de ArtuDesk para Windows distribuida mediante Microsoft Store. ArtuDesk permite compartir y controlar una pantalla entre participantes que aceptan una sesión de asistencia remota.

1. Responsable y contacto

ArtuDesk es publicado por JavierSoft. Para consultas de privacidad, solicitudes relacionadas con tus datos o preguntas sobre esta política, escribe a javier2315@gmail.com.

2. Información que trata ArtuDesk

ArtuDesk no requiere crear una cuenta y no incluye publicidad ni herramientas de analítica. La aplicación no solicita contactos ni ubicación precisa. Para prestar la función de asistencia remota trata estas categorías de información:

  • Datos temporales de señalización: un código aleatorio de sesión, su hora de creación y mensajes de negociación WebRTC (oferta y respuesta SDP). La negociación puede contener datos técnicos de red, incluidas direcciones IP y candidatos de conexión.
  • Contenido de pantalla: después de que la persona anfitriona aprueba la solicitud y elige un monitor, ArtuDesk transmite en directo la imagen de ese monitor al otro participante. La pantalla puede mostrar información personal o confidencial que el usuario haya abierto.
  • Acciones de control remoto: después de la aprobación, ArtuDesk transmite acciones de mouse y teclado para controlar el equipo anfitrión. El texto introducido mediante el control remoto lo recibe la aplicación que esté activa en ese equipo.
  • Diagnósticos locales: Windows puede guardar la fecha y etapa de un error, su tipo, código HRESULT y traza técnica en %LOCALAPPDATA%\ArtuDesk\diagnostico.log. El archivo puede rotar a diagnostico.log.previous al superar el límite interno. La aplicación no envía estos diagnósticos automáticamente al desarrollador.

ArtuDesk no graba sesiones ni conserva archivos de vídeo de la pantalla. No guarda el texto escrito, las imágenes capturadas, el código de sesión, la señalización SDP ni las direcciones de red en sus diagnósticos.

3. Cómo se usa y transmite la información

Firebase Realtime Database se usa para localizar la sesión e intercambiar temporalmente el código y la señalización necesaria para establecer la conexión. El tráfico de señalización se envía mediante HTTPS. ArtuDesk no solicita iniciar sesión en una cuenta de ArtuDesk; quien tenga el código puede intentar participar en la negociación, y la persona anfitriona debe aprobar el acceso antes de que comience la captura y el control.

Una vez establecida la sesión, WebRTC transmite la pantalla y las acciones de control entre los dos dispositivos con transporte cifrado. Se utiliza el servicio STUN público de Google para ayudar a establecer la conexión de red. Google puede tratar información técnica necesaria para prestar Firebase y STUN, conforme a sus propias políticas de privacidad. El otro participante recibe la pantalla compartida y las acciones de control durante la sesión.

ArtuDesk para Windows también puede conectarse con ArtuDesk para Android. En ese caso, el usuario de Android inicia la captura y debe aceptar el permiso de captura del sistema; para recibir acciones remotas debe habilitar el servicio de accesibilidad de ArtuDesk en Android. Windows recibe la pantalla de Android y puede enviar las acciones de control autorizadas.

4. Conservación y eliminación

Al establecerse la conexión, ArtuDesk solicita borrar de Firebase la oferta y la respuesta de señalización. Al cerrar normalmente la sesión, solicita borrar el registro de sesión. Si la aplicación se cierra de forma abrupta o no hay conexión, una solicitud de borrado puede fallar. El servicio no tiene configurada una limpieza automática por antigüedad; por ello, un registro abandonado puede permanecer hasta que se elimine desde el servicio.

Los diagnósticos permanecen en el almacenamiento local de Windows hasta que se eliminen manualmente o se desinstale la aplicación. Puedes borrarlos desde %LOCALAPPDATA%\ArtuDesk. Los proveedores de infraestructura pueden conservar registros técnicos conforme a sus propias políticas.

5. Consentimiento y controles

  • La persona anfitriona puede aceptar o rechazar cada solicitud de acceso.
  • La captura comienza después de la aprobación y se limita al monitor seleccionado por el anfitrión.
  • El anfitrión o el participante remoto puede finalizar la conexión. En las sesiones que incluyen ArtuDesk para Windows, la conexión se termina al llegar al límite de cuatro horas desde la aprobación.
  • Antes de compartir, cierra ventanas con información que no quieras mostrar y comparte el código únicamente con la persona invitada. No uses la aplicación para exponer datos que no quieras transmitir al otro participante.

6. Seguridad y servicios externos

La señalización se comunica con Firebase mediante HTTPS y la conexión WebRTC cifra el transporte entre dispositivos. El código de sesión sirve para localizar la negociación y no equivale a una cuenta autenticada. Mantén el código privado y verifica la solicitud antes de aceptarla. Firebase y STUN son servicios externos sujetos a sus propias condiciones y políticas de privacidad.

7. Solicitudes y cambios

Como ArtuDesk no mantiene cuentas ni un historial de sesiones para consulta, los registros temporales de señalización pueden no estar disponibles después de cerrar la sesión.
